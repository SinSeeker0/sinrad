SINRAD MAINTENANCE MEMORY
=========================

Purpose
-------
This file is long-term technical memory for anyone working on SINRAD.
Read it before changing the app.
Update it after every meaningful fix, feature, release, or discovery.

It exists to prevent old bugs from returning and to preserve the reason
behind important implementation choices.


HOW TO USE THIS FILE
--------------------
1. Read Current Snapshot, Product Rules, and the relevant bug entry.
2. Inspect the current code before assuming this file is still exact.
3. Preserve unrelated user changes in the working tree.
4. Reproduce a bug before changing its fix when possible.
5. Add or update a regression test with every recurring bug.
6. Do not mark work fixed until the packaged test build is checked.
7. Add the date, cause, fix, and test evidence to this file.

PRODUCT RULES THAT MUST NOT BE LOST
-----------------------------------
- Product names are “Sinrad” and “S.I.R”.
- Do not call it a “personal command center”.
- Do not restore the removed header logo.
- Keep the UI mostly square with restrained corner rounding.
- Keep the user’s update animations.
- Animation placement must remain adjustable per update phase.
- The sleep/arm button activates immediately without a confirmation.
- The user prefers short explanations and a brief TLDR.
- Avoid decorative microcopy, extra captions, badges, icons, and outlines.
- Do not add boxed letters, icon containers, badge-like chips, or decorative
  status markers anywhere in the app. For website or creator identity, use the
  real favicon/avatar. If it is unavailable, use a bare neutral symbol rather
  than a letter badge. Keep necessary counts and states as plain text.
- Avoid Apple/macOS visual language: no soft floating panels, glass effects,
  excessive rounding, pill-heavy controls, or centered launcher-style layouts.
- Prefer sharp, dark, content-dense layouts inspired by archive websites,
  Windows desktop software, and media libraries.
- The approved baseline is a warm editorial archive / desktop workbench:
  warm near-black surfaces, amber as the main interaction accent, compact
  Windows-style type, image-first cards, quiet dividers, and restrained
  6–8 px rounding. Do not drift back to blue/cyan dashboard styling.
- Settings lives at the top-right of the title bar and the same gear toggles it
  open and closed.
  Keep Escape and outside-click dismissal. Do not restore a separate Settings
  title row or duplicate close X.
- Keep Recently visited as quiet plain text over a Link card, never a boxed
  badge. Sort visited links above unvisited links by last-opened time.
- The footer page counter reports visible cards using the local Danbooru digit
  sprites. Keep the bundled attribution and do not replace it with a remote
  counter or network dependency.
- Do not restore the decorative processing/think bar or the oversized Screenies
  banner. Sidebar/module navigation must not expose horizontal scrollbars.
- Active tabs and selections use thin 1 px amber lines. Keep type small and
  avoid heavy all-caps headings except short navigation or section labels.
- Sidebar navigation icons are bare glyphs. Do not put borders, boxes, or
  button-like backgrounds around them, and do not restore a left active line.
- Category colors stay identifiable but muted toward the warm neutral palette;
  do not restore neon borders or glow effects.
- Do not repeat Open, Read, or Unread buttons on every content card. When the
  card has one obvious action, make the card itself perform it. Keep bulk or
  filter actions in the toolbar instead.
- Offline and Monitor labels stay exactly “Offline” and “Monitor” while active;
  active styling communicates state without adding “Exit” and changing width.
  Do not underline these mode buttons; use quiet background and text changes.
- Monitoring watchlist entries use artist-profile cards with a large banner,
  avatar, name, source, interval, and status. Do not return to admin-style rows.
- Do not place Pause, Check, or Remove buttons on every watcher card. Clicking
  opens the artist; watcher management stays in the card’s right-click menu.
- Monitoring notification control belongs in General Settings, not above the
  watchlist. The card open-mode setting is a switch, not a native dropdown.
- New Monitoring watchers default to a daily check. Existing watcher intervals
  remain user-controlled and must not be silently rewritten.
- Monitoring activity cards size to their own content. Clamp long titles and
  summaries with ellipses rather than stretching every card in the grid.
- The music/player feature is removed. Do not restore player UI, IPC, startup
  settings, bundled audio packaging, or console commands without a new request.
- The status bar shows current SESSION time and persisted TOTAL app-open time.
- Parking Lot titles, counts, and controls use quiet warm neutrals. Do not
  restore the old bright pink title, neon hover, or intense cyan/amber buttons.
- Helper text is for ambiguous, risky, or error-related actions only.
- Prefer spacing, alignment, and restrained dividers over nested card borders.
- Offline Reddit media uses one clean outer border around the player/gallery;
  do not add nested media borders. Author flair belongs beside the author,
  never in the post body. Preserve safe headings, emphasis, lists, quotes, and
  code formatting when the page exposes it.
- The Settings gear stays borderless at the far right of the title bar.
- Offline and Monitor controls keep their stable title-bar positions.
- Global search stays available in Offline Reader and Monitoring Mode.
- Settings has General, Parking, and Tools only. Do not restore Search there.
- Parking Settings only displays existing stacks; Parking actions stay in the
  Parking Lot module.
- Tools Settings contains link maintenance, Offline/media folders, the browser
  extension, and editable hotkeys.
- Prefer compact right-click menus for secondary and maintenance actions rather
  than visible button rows. Keep Back/navigation, primary create/filter actions,
  switches, hotkey fields, gallery controls, and media playback controls visible
  when they are needed.
- Give a rough usage percentage before starting substantial work.
- Build test copies before releases.
- Release only after the user explicitly says to release.
- Increment the edit counter once per meaningful completed change batch.
- Full URLs identify links. Same website does not mean duplicate page.
- YouTube must remain the main category for YouTube links while preserving
  any other categories already assigned to the link.
- Selecting multiple link categories uses AND logic. A card must contain
  every selected category.
- Global search must never expose or search vault passwords.
- Offline Mode is a separate experience. When enabled, the normal modules,
  sidebar, and console disappear until the user exits Offline Mode.
- Monitoring Mode is also a separate experience. It hides normal modules,
  the sidebar, and console, and is mutually exclusive with Offline Mode.


ARCHITECTURE MAP
----------------
main.js
- Electron main process and privileged operations.
- Window identity, protocol handling, extension bridge, file access,
  storage, updates, screenshots, hotkeys, Offline Feed syncing, and monitor
  polling/notifications.
- Network requests belong here, not in the renderer.

preload.js
- Narrow IPC bridge between the isolated renderer and main process.
- Add new renderer privileges here rather than enabling Node integration.

index.html
- App shell, title bar, status bar, modals, and root containers.
- Content Security Policy intentionally blocks renderer network access.

assets/renderer.js
- UI state, rendering, actions, modals, searching, and mode switching.
- EDIT_COUNT is maintained here.

assets/index.css
- Main UI, update UI, command palette, Offline Reader, and Monitoring styling.
- Update GIF position variables are near the end of this file.

assets/shared.js
- Reusable URL, category, duplicate, and validation logic.

extension/
- Opera/Chromium Manifest V3 browser extension.
- The installed extension is copied to a stable per-user directory.

lib/
- Security, screenshots, thumbnails, link checking, Offline Feed storage,
  Monitoring storage, and source adapters.

test/
- Unit and regression tests. Add coverage for every repeated failure.

scripts/ui-smoke.js
- Hidden Electron test for real add flows, global search, and mode switching.


DATA AND STORAGE MAP
--------------------
Production Electron userData:
- sinrad-data.json: encrypted main application state.
- sinrad-data.json.bak: last valid main-state copy.
- thumbnail-cache/: generated screenshot thumbnails.
- browser-extension/: stable unpacked extension installed in Opera.
- extension-bridge-key: installation-specific extension authentication.
- offline-feed/feed.json: Offline Reader sources and normalized feed text.
- offline-feed/media/: downloaded Offline Reader images.
- offline-feed/reddit-auth.json: Reddit OAuth credentials, encrypted with
  Electron safeStorage when OS encryption is available.
- monitoring/monitoring.json: watcher settings, baselines, errors, and
  normalized monitoring activity.
- monitoring/media/: locally cached creator avatars, banners, and post
  thumbnails. Renderer images must be loaded through monitoring-media IPC.
- site-preview-cache/: resized Open Graph images, YouTube thumbnails, and
  favicons. It is disposable and is never placed in encrypted app state.

Development uses a separate Sinrad-Dev userData folder.
Never let a test build overwrite production data.

The main encrypted state has a 10 MB safety limit.
Large Offline Reader content must remain in offline-feed/, not state.


FEATURE INVENTORY
-----------------
Vault
- Encrypted local credentials.
- Add, edit, delete, reveal, copy, favorite, priority, and search.
- Clipboard password clearing after 45 seconds if unchanged.
- Website previews receive only the saved URL; credentials never leave the
  encrypted store.

Links
- Full-URL bookmarks, search, categories, favorites, multiple categories,
  exact-duplicate review, smart rules, and manual health checking.
- YouTube links automatically receive YouTube as their main category.
- Rich previews prefer YouTube thumbnails or page Open Graph images and fall
  back to the website icon.

Parking Lot
- Temporary tab stacks separate from permanent Links.
- Can send individual links or stacks to Links.
- Uses small cached website icons instead of full preview images.

Quick Folders
- Saved folders, categories, favorites, and Pet Recents integration.
- Uses the newest image directly inside a saved folder as its local preview.

Screenies
- Watches screenshot folders.
- Cached thumbnails, pagination, copying, revealing, categorizing,
  slideshow, and Google Lens handoff.

Browser extension
- Quick Save sends the current page directly to Links.
- Bulk actions park all tabs or park and close acknowledged tabs.
- Uses an authenticated localhost bridge.

Norma and desktop extras
- Floating pet, folder shortcuts, music, boot animations, uptime,
  update flow, autostart, and sleep timer.

Global search
- Searches modules without searching vault passwords.
- Ctrl+Shift+F focuses global search.

Command palette
- Opens from the title-bar button or Ctrl+Shift+P.
- Includes navigation, add actions, maintenance actions, backup, updates,
  and Offline Reader mode switching.

Undo
- Ctrl+Z restores supported destructive changes from this app session.
- Undo history is intentionally session-only at present.

Offline Reader — unreleased MVP
- Dedicated full-app mode, not a normal sidebar module.
- Unified feed model for future Reddit, YouTube, and X adapters.
- Offline text, cached Reddit-hosted images, useful top comments,
  dates, original URLs, downloaded dates, unread state, and favorites.
- Subreddit subscriptions with item limit, interval, sort, and comment count.
- Exact source-key deduplication.
- Configurable retention and maximum item count.
- Favorites survive retention pruning.
- Automatic catch-up sync while SINRAD is running.
- Reddit OAuth uses a user-created approved client ID.
- Renderer never directly contacts Reddit.
- Reddit API rate-limit headers and HTTP 429 are respected.

Monitoring Mode — unreleased MVP
- Dedicated full-app mode, separate from normal modules and Offline Mode.
- Accepts Pawchive and Bakemono creator links as the same Pawchive-backed
  watcher, so users can paste either frontend URL.
- Accepts F95zone thread links, including page links, and normalizes them to
  one watcher per thread.
- First check records a quiet baseline and never floods old entries.
- Later checks deduplicate updates by stable post/reply IDs.
- Configurable per-watcher intervals, pause/resume, manual checks, retention,
  activity search, read/unread state, and Windows notifications.
- Clicking a notification opens and focuses the matching Monitoring entry.
- Automatic checks run while SINRAD is open and catch up on the next launch.
- Monitoring never downloads attachments automatically. Explicit user downloads
  accept only source-exposed, validated Pawchive file paths and never bypass
  access controls or paywalls.
- Pawchive watcher cards use locally cached creator avatars and banners.
- New Pawchive activity uses locally cached image-first gallery cards.
- The first Pawchive check quietly seeds up to 24 recent posts as read cards,
  so the gallery is useful immediately without sending old notifications.
- Only allowlisted Pawchive image routes are accepted; files are size-limited,
  signature-checked, and never loaded directly by the renderer.
- Pawchive reader attachments are one large item per row, stacked vertically.
  Preserve their natural image proportions and do not return to a multi-column
  thumbnail grid.


BUG AND REGRESSION MEMORY
=========================

BUG-001 — release.bat says commit or stash changes first
Status: expected safety behavior.

Symptom:
The release helper stops before publishing.

Cause:
release.js intentionally refuses to release a dirty working tree.

Correct handling:
- Review and test the changes.
- Commit the intended files.
- Confirm the main branch is clean.
- Run release.bat only after explicit user approval.

Never “fix” this by removing the clean-tree check.
It prevents partial or accidental releases.


BUG-002 — Windows update creates a second taskbar icon
Status: fixed in v2.0.28. High regression risk.

Symptoms:
- The pinned Sinrad icon stays idle.
- A second active Sinrad/Electron icon appears after an update.
- Windows Search may label the app Electron.

Root causes previously encountered:
- Packaged and running windows used inconsistent Windows app identities.
- Window icon settings could make Chromium use a different runtime identity.
- Installer identity and application identity changed between builds.

Current fix:
- Keep PACKAGED_APP_ID exactly “com.sinrad.desktop”.
- Development uses “com.sinrad.desktop.dev”.
- app.setAppUserModelId is set before windows are created.
- mainWin.setAppDetails uses the packaged executable.
- On Windows, BrowserWindow omits the icon so Chromium uses the icon
  embedded in Sinrad.exe.
- Keep package build.appId stable.
- Keep NSIS guid, productName, and shortcutName stable.

Regression guard:
test/updater.test.js checks runtime and installer identity.

Verification:
- Install/update over the existing installation.
- Start from the already pinned shortcut.
- The active window must group under that same pin.
- A development test app may intentionally have a separate identity.


BUG-003 — grey Electron icon instead of Sinrad icon
Status: fixed. Related to BUG-002.

Cause:
Electron window icon behavior on Windows differed from the embedded EXE icon.

Fix:
- Use the correct multi-resolution icon.ico in the build.
- Do not set BrowserWindow.icon on packaged Windows builds.
- Do not replace icon.ico with a low-quality upscaled source.

Verification:
Check the EXE, Windows Search, Start menu, taskbar, and installer shortcut.


BUG-004 — extension says S.I.R not connected / HTTP 403
Status: fixed. High regression risk.

Cause:
- The localhost bridge was hardened to require an installation key.
- Older extension files did not contain the current bridge key.
- Reloading Opera alone did not help when an old SINRAD build was running.

Fix:
- Generate a per-installation extension-bridge-key.
- Copy the bundled extension into userData/browser-extension.
- Replace __SINRAD_BRIDGE_KEY__ while copying background.js.
- Require both bridge authentication and the short-lived local token.
- Bind the server only to 127.0.0.1.

Important test rule:
Close every SINRAD process before testing a newly packaged build.
The single-instance lock can focus an older running build instead.

Opera setup:
Load the stable userData/browser-extension folder once.
SINRAD updates that folder in place. Reload the extension only when needed.


BUG-005 — new tabs are not saved because they share a website
Status: fixed.

Cause:
Earlier duplicate logic treated a host/site as the identity.

Fix:
Use the normalized complete URL as identity.
Paths, queries, and case-sensitive path content remain meaningful.

Example behavior:
example.com/feed and example.com/post/123 are different links.
Only identical complete normalized URLs are duplicates.

Regression guards:
- test/links.test.js
- Exact duplicate review tests.


BUG-006 — extension Quick Save goes to Parking Lot or takes two clicks
Status: fixed previously; bulk batch and isolation repair awaiting user test.

Desired behavior:
- The first context-menu Quick Save action saves the current page to Links.
- Bulk actions remain directly below it.
- Park All stores tabs in Parking Lot.
- Park All and Close closes only tabs SINRAD confirms it saved.

Do not merge Links and Parking Lot semantics again.

2026-09-01 hardening:
- Park All sends one authenticated tab batch and waits for one durable save
  acknowledgement instead of posting every tab separately.
- One batch produces one completion animation and one app notification.
- Park All and Close closes tabs only after the complete batch is persisted.
- A parked item is src="park" with inLinks=false. Its automatic category must
  never move it into permanent Links.
- Stack list, open, rename, send, and delete actions use parked items only.
- Extension 1.1.7 contains the batch request. Reload the stable extension
  after starting the new test build.

Opera limitation:
Opera controls where extension menus appear in its native context menus.
SINRAD can control its menu items but not every Opera menu placement.


BUG-007 — screenshot thumbnails are slow, delayed, or broken
Status: improved. Continue monitoring on very large libraries.

Causes addressed:
- Full-size image decoding during grid rendering.
- Repeated thumbnail generation.
- Too much simultaneous work.
- Cache entries not invalidating after source-image changes.

Current fix:
- Disk thumbnail cache keyed by path, size, and modification time.
- Cached reads before generation.
- Maximum four active thumbnail generation jobs.
- Pagination and content-visibility for large grids.
- Cache pruning by age, file count, and total bytes.

Regression guards:
- test/thumbnail-cache.test.js
- test/screenshots.test.js

Do not cache only the file path. Changed images must get a new key.

BUG-014 — Ctrl+Z does not restore a deleted link
Status: improved in unreleased work. Verify in packaged test build.

Cause:
Focused inputs or controls could receive the key before the app handler.

Fix:

- Keep the last 20 supported mutations in an in-memory undo stack.

BUG-015 — Ctrl+Shift+P command palette does not open
Status: fixed in unreleased work. High regression risk.

Cause:
Electron or a focused renderer control could intercept the shortcut before
the document-level JavaScript listener.

Fix:

- main sends the “command-palette” event through preload.
- renderer opens the palette from that privileged event.
- A renderer capture listener remains as a fallback.

Regression guard:
test/regressions.test.js checks all three layers.

Testing warning:
Confirm the bottom bar shows the expected edit count.
If an older installed SINRAD is still running, the test EXE can focus it
instead of launching the new build because of the single-instance lock.

BUG-017 — local storage corruption or failed restore overwrites good data
Status: fixed. Security-critical.

- Atomic temp-file write and previous-file backup.
- If encrypted files cannot be read, writes lock instead of replacing data.
- Backup restore keeps the previous in-memory state until save succeeds.
- Development and production data directories are separated.

Never weaken the locked-write behavior to make an error disappear.

BUG-020 — Offline Reader must still work with internet disconnected
Status: implemented in unreleased MVP; real-world verification pending.

Design that must be preserved:
- Normalize source content into local feed items.
- Store text and metadata in offline-feed/feed.json.
- Download approved image media into offline-feed/media/.
- Renderer reads only the local index and cached media while browsing.
- Opening the original URL is optional and is the only reading action that
  requires the external website.
- Duplicate identity is platform plus stable source item ID.
- Network and OAuth stay in main.js.
- Source adapters return the same normalized feed format.
- Browser snapshots keep the full MHTML as the source of truth, but also save
  the visible post title, author, community, body, date, counts, and an approved
  local gallery in the feed index so cards do not become generic placeholders.
- A browser save can retain up to 20 ordered Reddit gallery images and up to 80
  comment entries that are loaded in the page DOM. Media is copied locally and
  comments are stored as sanitized text with author, score, date, and depth.
- Saved Reddit details use a large contained carousel and a flat indented
  comment thread. The internal reader approximates the post content hierarchy;
  it does not copy Reddit's account controls or community sidebar.

CACHED MODULE PREVIEWS — EDIT #182
==================================

Goal:
- Make saved items recognizable at a glance without turning every module into
  a live web browser.

Implementation:
- lib/site-preview.js performs bounded, read-only HTTP(S) requests in the main
  process. It extracts Open Graph/Twitter images and favicons without running
  page scripts. YouTube thumbnails are derived from the video ID.
- Every redirect and image request is DNS checked. Localhost, private network
  addresses, file URLs, and unsupported image data are rejected.
- assets/renderer.js receives data URLs through narrow IPC. Previews load only
  when cards approach the visible area and the in-memory renderer cache is
  bounded.
- main.js stores resized previews in site-preview-cache. Repeated visits use
  disk cache and failed requests cool down for 30 minutes.
- Folder previews only inspect exact folder paths already saved in Quick
  Folders. They do not recurse and never read outside those saved folders.
- Vault preview requests include only the URL. Never add username/password
  fields to the preview IPC payload.

Fallback behavior:
- Links/Vault: rich image -> favicon -> local placeholder.
- Parking Lot: favicon -> local letter placeholder.
- Quick Folders: newest direct child image -> folder icon placeholder.

Regression guards:
- test/site-preview.test.js checks metadata parsing, safe schemes, YouTube URL
  handling, and image signature validation.
- scripts/ui-smoke.js checks preview hydration in Links, Vault, and Folders.
